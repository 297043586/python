# 第二十二批更新说明

## 二层环路检测重构(「🩺 二层体检」)

环路研判独立到 `l2loop.go`，按证据可信度分层，并用同一台设备上的其他现象互相印证。

### 修复的问题

- **同一台设备上的环路以前完全不报**：网线两头插回同一台交换机、两个口接到同一台傻瓜交换机，是最常见的环路形态，但之前只检查"跨设备"漂移。现在使用 VLAN+MAC 粒度的转发表：同一 VLAN 内一批 MAC 在两个逻辑口之间来回即报出。
- **真实环路反而被掩盖**：环路时接入口会学到核心 / 上游交换机自己的 MAC，原逻辑据此把这个接入口当成"朝向核心的级联口"，结果跨设备漂移被去重掉，还会误报成"没开 LLDP：下面是已纳管的 CORE"。现在环路判断只依赖 LLDP / 聚合 / 端口属性，认定的疑似环路口不再出现在「没开 LLDP」「疑似私接」结论里。
- **误报多**：以前 1 个 MAC 出现在两台设备的接入口就报 warning，无线漫游、终端换口都会触发。现在按 MAC 数量分级，并要求佐证。
- **只到设备对，不到端口**：跨设备漂移改为按涉及的具体端口分组，结论直接指出该断哪个口。

### 证据分层

| 证据 | 等级 |
| --- | --- |
| 同一 VLAN 内，被监控设备(上游交换机 / 网关)自己的 MAC 从同一台设备的两个口学到 | critical(生成树正常时不会出现) |
| 同一台设备同一 VLAN 内 MAC 在两个口之间来回 | ≥10 个 critical，≥3 个 warning，否则 info |
| LLDP 显示设备 X 接在 A 口，X 的 MAC 却从没有 LLDP 邻居的 B 口学到 | warning |
| 跨设备接入口同时学到相同 MAC | ≥20 个 critical，≥5 个 warning，否则 info |
| 无 MAC 证据，但同一台设备广播风暴与生成树变化同时出现 | warning |

- 佐证：涉及设备本轮有广播风暴、生成树变化超过阈值或 ≥3 个端口 10 分钟内抖动时，等级上调一档，佐证内容列在证据里。
- 聚合组成员口之间的 MAC 来回(负载分担)、没有确切 VLAN 的转发表行不参与判断。
- 结论区分"都是接入口 / 上联与接入口之间 / 都是上联口"三种形态，给出对应的排查方向。
- 「多台设备同时广播风暴」的排查步骤优先列出 MAC 漂移定位到的疑似环路口，其次才是风暴最高的接入口。
- 新增按厂商的命令：查看 MAC 漂移记录(华为 `display mac-address flapping record`、H3C `display mac-address mac-move` 等)，以及接入口环路检测配置(华为 loopback-detect、H3C loopback-detection、锐捷 RLDP、Cisco BPDU guard)。

## 升级与验证

- 替换 `netmon.exe` 并重启，无需改配置；下一轮巡检后在「二层体检」中生效。
- `go vet`、`go test`(新增 `l2loop_test.go`：同设备接入口环路、上游 MAC 双口学到、LLDP 路径异常、聚合口排除、少量漂移分级与佐证升级、风暴 + 生成树)、`go build -o netmon.exe .`：通过。
