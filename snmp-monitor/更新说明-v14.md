## 一、MAC 总表不准(很多终端都算在核心上)

**原因**: 单台设备只能靠"这个口有没有 LLDP 邻居、学到的 MAC 够不够多"来猜它是不是上联口。常见误判:
- 核心的聚合口(比如 AggregatePort 6)下面接的是一台接入交换机, 但 LLDP 是在**成员口**上报的, 聚合口本身查不到邻居; 下面终端又不多, MAC 数没到阈值 —— 聚合口被当成"接入口", 终端看起来像直接插在核心上;
- 所有设备都只在上联口见过某个 MAC 时, 以前按设备 IP 挑代表, 经常挑中核心。

**改法**(新增 `netctx.go`, MAC 总表 / ARP 总表 / 二层体检共用的"全网上下文"):
- 采集时多读每台设备**自己的 MAC**(桥 MAC + 三层口 MAC)和**全部接口地址 + 掩码**;
- 判断一个口"朝向谁": LLDP 邻居、聚合成员口的邻居、或者这个口学到了另一台被监控设备自己的 MAC —— 都算朝向那台设备;
- 算出每台设备的**层级**(离核心多远);
- 归属顺序:
  1. 这个口朝向另一台被监控设备, 而那台也学到了这个 MAC → 这条是**路过**, 真正位置在下游;
  2. 剩下的只留接入口; 分布在多台设备上时**层级更深(更靠近终端)的优先**, 同一层级分不开才算"跨设备漂移";
  3. 全都是上联口(下游设备没采到 MAC 表)时, 挑层级最深的那台, 不再按 IP 挑。
- 被监控设备自己的 MAC 在总表里标出属于哪台设备。

## 二、ARP 总表"一 MAC 多 IP"不准

三层交换机(比如 LZC-L4 有二十多个 VLANIF)所有接口共用一个 MAC, 在核心的 ARP 里就是"一个 MAC 对应一堆 IP", 以前会被当成异常。

**现在按设备自己的 MAC 和接口地址分类**:
- 是某台被监控设备自己的 MAC → 标成"设备自身的多个接口", 不算异常;
- `/30`、`/31` 这类地址标成**互联地址**, 其余标成**网关地址**;
- 剩下真正是一个终端占了多个 IP 的才标出来。

## 三、二层体检

### MAC 漂移误报
`00:0E:A9:01:76:34: DC-L4-S18000 AggregatePort 6 / ZBC-L4 GigabitEthernet 2/0/18` 这类: AggregatePort 6 是核心下联 ZBC-L4 的聚合口, 终端真正接在 ZBC-L4 上, **不是漂移**。现在漂移检测(包括设备详情里的诊断)跟 MAC 总表用同一套归属结果, 这种情况算"路过", 不再报。

### 疑似私接: 拆成几类
- 对端是交换机但**没开 LLDP**;
- 对端开了 LLDP、能看到名字 / 管理 IP, 但**没纳管** —— 直接给「＋ 添加到监控」按钮;
- 分辨不出的归为"未知"。

### ARP 欺骗: 区分地址类型
- **网关地址**对应的 MAC 不是设备自己的 → 严重(有人发伪造 ARP 应答, 终端流量会被引走);
- **互联地址**(/30、/31)对应的 MAC 不对 → 警告(多半是对端 ARP 没老化 / 刚换过设备或板卡, 或者这个地址在别处也配了);
- **管理地址**对应的 MAC 不对 → 警告(IP 冲突或欺骗);
- 老数据还没采到设备接口 MAC 时只给提示, 升级后下一轮巡检就能分清。

### 一 MAC 多 IP
同第二条, 设备自己的多个接口地址不再报。

### 排查思路
不再是一篇通用文章, **每一条问题下面给对应的排查步骤**, 带上具体设备、具体端口、具体 MAC / IP 和按厂商生成的命令(比如在哪台设备上查哪个 MAC 的 ARP)。

## 四、3D 机房 / 2D 机柜面板

**3D 机房**
- 打开的机柜, 镜头转到**背面时后门自动打开**;
- **机房门能开了**: 点一下开 / 关, 镜头走到门附近(3 米内)自动开;
- 卡顿: 阴影改成静态阴影(只在场景变化时重算), 鼠标悬停检测限制为每帧最多一次;
- **全屏菜单**: 编辑模式下工具条跟进全屏区域, 能看见; 不编辑时全屏画面干净, 右上角「☰ 菜单」临时展开工具条和右侧面板。

**2D 机柜面板 · 框式交换机槽位**
以前槽位号取错了段: 三段端口名取成了机框号, 两段端口名全都塞进一块"?"板卡。现在按端口名里槽位号的位置识别:

| 写法 | 例子 | 槽位 |
|---|---|---|
| 两段 | `3/1` | 第一段 |
| 三段 · 机框/槽位/端口(锐捷 VSU 等) | `1/3/1` | 第二段(多台机框时带上机框号) |
| 三段 · 槽位/子卡/端口(华为 S7700 等) | `3/0/1` | 第一段 |
| 四段 · 机框/槽位/子卡/端口(H3C IRF) | `1/3/0/1` | 第二段(多台机框时带上机框号) |

三段的两种写法优先靠"哪一段取值变化多"区分; 多机框且数量打平时, 再看各框是否重复出现相同的第二段槽号。第二段出现 `0` 时优先按"槽位/子卡/端口"处理。所以 `1/1/x` 和 `1/3/x` 现在是两块板卡; 只有管理口的是主控板(MPU)。

显示设置里新增 **「框式交换机隐藏空槽位」**(只画有板卡的槽), 原来的"压缩空槽位"保留。

- **备份窗口**: 表格和下面的配置查看区之间加了**可拖动的分隔条**; 双击分隔条或点「⤢ 放大」把配置区放到最大; 配置 / 对比在下半部分铺满, 不再限制 60% 屏高;

## 六、LLDP 对端 IP / 一键添加设备

- 对端管理 IP 的采集更全: 整张 `lldpRemManAddrTable` 都读; 对端没带管理地址时, 用对端机箱 MAC 在全网 ARP 里反查 IP;
- 能看到 IP 的邻居可以直接添加:
  - **2D 拓扑**: 未监控邻居小圆点 → 侧栏「＋ 添加到监控」;
  - **设备管理 → 🔍 LLDP 发现**: 列出全网 LLDP 看得到但没纳管的邻居, 点「添加」把 IP 和名字填进表单, 填团体名保存即可;
  - 设备详情端口表的 LLDP 列(「+监控」)、二层体检的"疑似私接"里也有入口。

## 七、游客权限

「👥 账号权限 → 游客访问」(只有管理员能改):
- **关闭游客访问**: 不登录什么都看不到, 打开页面直接要求登录;
- 或者**只开放部分页面**(比如只给看仪表盘和大屏, 不给看 MAC / ARP 总表这种带终端信息的);
- 游客看不到的菜单按钮会隐藏; 登录后的账号查看不受限制, 写操作仍按原来的权限走;
- **没配置过时默认"游客可以看全部"**, 跟升级前一样, 升级后需要管理员自己去收紧。

## 八、服务器硬盘占用 / 数据保留

系统设置新增 **「💽 存储」** 页:
- 数据目录所在磁盘的已用 / 剩余(超过 85% 变橙、95% 变红, 90% 以上给出处理建议);
- data 目录下各类数据分别占多少: 告警历史 / 配置备份 / 巡检报告 / 趋势曲线 / 下发审计日志 / 崩溃日志 / 其他;
- 统一设置"存多少天、多少份":

| 数据 | 份数 | 天数 |
|---|---|---|
| 配置备份 | 每台保留份数(原有) | **新增**, 0 = 不按天清; 每台最新一份永远保留 |
| 巡检报告 | 最多保留份数(原有) | **新增**, 0 = 不按天清 |
| 配置下发审计日志 | — | **新增**, 0 = 永久保留 |
| 告警历史 / 趋势曲线 | — | 仍在「告警」「SNMP 采集」里改, 这里显示并可跳转 |

- 按天清理**每 6 小时**跑一次, 保存设置后立即跑一次; 份数调小后多出来的立即删掉;
- 磁盘剩余不到 5% 或不到 1 GB 时控制台打印警告。

## 九、窗口之间可以返回

- 从一个窗口打开另一个窗口(比如 二层体检 → 设备详情 → MAC 总表), 新窗口叠在上面, 标题栏左边有 **「← 返回」**;
- 点 × 或按 Esc 回到上一级, 不再整个关掉;
- 设备详情里从一台设备跳到另一台(点 LLDP 邻居等), 也能一路返回;
- 登录框、改口令这种小对话框没有返回按钮。
