# 第二十三批更新说明

## MAC 表 / ARP 表数据修正(采集与归属重构)

转发表 / ARP 的整理逻辑从 `inspect.go`、`collect_fdb.go` 里拆到新文件 `fdb_tables.go`(纯数据处理, 不碰 SNMP, 可单元测试); `collect_fdb.go` 只负责 walk。

### MAC 转发表(采集)

- **VLAN 列可能整列是错的**: `dot1qTpFdbTable` 索引的第一段是 FdbId(过滤数据库号), 不是 VLAN 号。华为 / H3C / 锐捷大多两者相等, 所以看起来没问题; FdbId 是内部序号的设备(Juniper、部分 HP / Dell / 白牌)VLAN 全错, 按 VLAN 筛选、ARP 定位、同 VLAN 漂移判断跟着错。现在读 `dot1qVlanFdbId` 换算; 多个 VLAN 共用一个 FdbId(共享学习)时 VLAN 记为未知, 不再瞎填; 设备没有这张表时仍按 FdbId = VLAN。
- **凭空出现的"有歧义"MAC**: 同一个 MAC 在 Q-BRIDGE 表(带 VLAN)和传统 BRIDGE 表(不带 VLAN, 往往只反映默认 VLAN 或是旧值)里的口被并到一起, 造出"多个口都学到"。现在 Q-BRIDGE 有这个 MAC 时, 传统表里它的行不再参与。
- **端口 MAC 数 / 上联口判断偏差**: 以前一个 MAC 只记到 ifIndex 按**字符串**排序的第一个口上("100" 排在 "12" 前), 上联口计数偏小或偏大, 进而影响"上联/接入"判断。现在是每个口学到的不同 MAC 数(跟交换机按端口查 MAC 一致), 而且不随裁决变化。
- **静态 / 黏滞 MAC 消失**: 以前只收 `learned(3)`, 静态配置、port-security 黏滞的终端整个不在表里。现在只排除 `invalid(2)` 和 `self(4)`。
- **聚合口被当成接入口**: LLDP 在成员口上报、MAC 学在聚合口上, 单台设备视角下聚合口没有邻居。现在成员口有 LLDP/CDP 邻居的聚合口也算上联口(端口表、MAC 表、ARP 表都生效)。
- **per-VLAN 团体名(`vlan_community_format`)补采不完整**: 以前只对"ARP 里没定位到的 VLAN"补查, 结果只回填 ARP 表, MAC 表 / MAC 转发表里没有; 补查在 MAC 表生成之后进行, 还会改动上一轮的缓存数据。现在在大表采集阶段对全部已知 VLAN(端口 VLAN 成员、VLAN 名称表、VLANIF, 上限 256 个, 跳过 1002-1005)补采, 带 VLAN 号跟普通转发表行一起落定后再缓存。Cisco 等必须 per-VLAN 上下文才能看到 MAC 表的设备, MAC 表从"只有 VLAN 1"变成完整。巡检耗时里多一项「MAC表(按VLAN)」。

### 设备详情: MAC 表 / ARP 表(生成)

- **MAC 表的 VLAN**: MAC 跨多个 VLAN 时以前直接退回端口 PVID(trunk 口上就是 native VLAN)。现在取这个 MAC 在所选端口上的转发表行的 VLAN, 多个用逗号分隔。
- **ARP 的 VLAN**: 优先取 ARP 所在的 VLANIF(这条 ARP 就是在这个 VLAN 里解析的, 标为确切值), 其次才是转发表、端口 PVID。
- **ARP 的端口**: 优先用同一 VLAN 的转发表行。以前一律用按 MAC 合并后的位置, 路由器 / 防火墙 / 三层设备的 MAC 在不同 VLAN 走不同口时会给出另一个 VLAN 的口; 现在本 VLAN 里没有转发表行(已老化)时显示"未定位", 不再借别的 VLAN 的口。
- **路由口 / 三层聚合口上的 ARP**: 转发表里没有这类 MAC, 以前一律"未定位"。现在直接定位到 ARP 所在的口。
- **ARP 采集**: 过滤 `ipNetToMediaType` / `ipNetToPhysicalType` 为 `invalid(2)` 的失效行; 以前按"IP 以 .255 结尾"丢弃, /23、/22 网段里 x.x.x.255 的正常主机整个看不到, 现在按全 F MAC、组播 / 受限地址过滤; `ipNetToPhysicalTable` 省略长度字节的索引也能识别。

### 全网 ARP 总表 / MAC 总表

- **ARP 总表的"接入口"其实是核心的下联口**: 以前直接用 ARP 来源设备(核心 / 网关)上这个 MAC 所在的口, 终端看上去都接在核心上。现在新增「接入位置」列, 取跟 MAC 总表同一套全网归属结果(沿途路过的上联口已去掉), 显示「接入设备 · 端口」, 点击直达那台设备的端口; 只定位到上联口(下游交换机没纳管 / 没采到 MAC 表)、跨设备漂移分别标出。原来的设备列改为「ARP 来源设备」, 下面小字是来源设备上的口。设备筛选同时匹配来源设备和接入设备; 类型筛选新增"只定位到上联口""未定位"(去掉了不会再出现的"跨设备关联")。
- **同一 (IP, MAC) 留哪条**: 以前按设备顺序谁先来留谁, 可能留下跨设备关联借来的行。现在本机 ARP 解析到的优先, 其次 VLAN 确切、已定位的。
- **MAC 总表的终端 IP 来回变**: 一个 MAC 有多个 IP 时以前取"第一台设备报的第一条", 设备顺序一变 IP 就变。现在优先本机解析的, 同类取地址最小的; 跨设备关联借 IP 时同样按地址最小取。
- 二层体检里 "IP 冲突" 的证据改为显示终端的接入位置。
