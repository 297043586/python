# 第二十一批更新说明

本批修正第二十批「路由协议、类型和年龄显示」「锐捷电口 SFP 识别」中仍存在的问题。

## 路由表：IP-FORWARD-MIB 列号错位（协议显示 -1 / 未上报的根因）

- `inetCidrRouteStatus` 应为 `.1.3.6.1.2.1.4.24.7.1.17`，此前误用 `.16`（Metric5，未使用时为 `-1`），导致新版表的路由全部被当成非活动行丢弃，回退到旧表。
- `ipCidrRouteTable` 的列号整体错位：此前把 Metric1 当类型、Metric2 当协议、Metric3 当年龄、类型当 Metric。现按 RFC 2096 更正为 Type `.6`、Proto `.7`、Age `.8`、Metric1 `.11`，并新增 Status `.16` 过滤非活动行。第二十批说明中“`-1` 是设备未上报协议”的判断，实际多数是读到了 `-1` 的 Metric2 列。
- 旧版 `ipRouteTable` 新增读取 ipRouteAge（`.10`）。

## 路由表：采集重构

- IPv4 优先读 `inetCidrRouteTable`；若该表没有 IPv4 行，或部分行的协议/类型枚举无效，自动读取 `ipCidrRouteTable` / `ipRouteTable`，按“目的网段 + 下一跳”匹配补全（只替换无效字段，不覆盖设备给出的有效值）。来源栏会显示补全条数。IPv6 优先新版表，无 IPv6 行时回退 `ipv6RouteTable`。
- 各表枚举分别解码：鼠标悬停在协议/类型上显示原始值及所用的表。IPv6 协议 `4` 更正为“邻居发现”（原误标为 ICMPv6），`6` 显示为 OSPFv3；新增 IANA 协议 `20`（TTDP）。
- 并行读取的列若超时，会在主会话上重试一次；仍失败的列会在页面提示，而不是静默显示成“未上报”后被长期缓存。
- metric / 年龄缺失或无效（负数、`0xFFFFFFFF`）统一显示为 `-`，与真实的 `0` 区分；年龄显示为“x天x小时 / x分x秒”。
- 路由按地址数值排序（IPv4 在前），不再出现 `10.x` 排在 `9.x` 前面的问题。
- 路由缓存增加版本号：旧版本保存的错误解码数据不会再直接显示，首次打开路由页自动重新读取；仅在重新读取失败时作为兜底并注明“由旧版本解码”。

## 锐捷电口 SFP 识别

- 修复：锐捷老固件“整数位/小数位/符号位”拼装路径此前没有跳过电口模块，`-40 dBm` 仍会显示，现已跳过。
- 收发器类型/连接器文本识别改为按词判断，新增识别锐捷型号中的 `GT`（如 `Mini-GBIC-GT`）、`10GBASE-T`、`RJ-45`、DAC/`CU` 直连铜缆；能识别 LC/SC/MPO、SX/LX/SR/LR、SM1310/MM850 等光模块。
- 锐捷收发器文本优先于 MAU-MIB：combo 口 MAU 报铜介质而实际插着光模块时，不再误屏蔽光功率。类型与连接器矛盾时不做判断。
- 兜底：收发器类型 MIB 未开放时，锐捷设备同一端口 RX 与 TX 同时 ≤ -40 dBm 视为无 DDM 模块（电口 SFP、DAC），不显示该读数也不产生光功率告警；巡检来源中会注明数量。仅 RX 为 -40（无光）、TX 正常的光口照常显示。

## 升级与验证

- 替换 `netmon.exe` 并重启。`data/routes.json` 中的旧缓存无需手动删除，首次打开各设备路由页会自动按新规则重读。
- `go vet`、`go test`（含新增 `api_routes_test.go`：OID 列号、各表枚举解码、补全合并、索引解析、排序、收发器介质识别）、`go build -o netmon.exe .`：通过。
- 未连接真实设备验证；锐捷 `.165/.166` 文本列是否开放仍取决于固件。
