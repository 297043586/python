# 第二十批更新说明

## 路由表缓存与读取提速

- 路由表第一次打开时读取 SNMP 并保存到 `data/routes.json`；以后打开设备详情会直接显示已保存的数据，不会因巡检时间戳变化而再次读取。
- 「刷新路由表」按钮会重新读取设备并更新缓存。刷新失败时保留并显示上次保存的数据，同时提示失败原因。
- 路由各列和接口名称通过多条 SNMP 会话并行读取，减少大路由表逐列等待的时间。路由表仍只在用户打开路由页或主动刷新时读取，不加入全网定时巡检。
- 缓存按设备地址、设备 ID、SNMP 版本和团体名指纹区分；团体名不会写入路由缓存文件。

## 路由协议、类型和年龄显示

- 按 IP-FORWARD-MIB 枚举解码路由协议；标准协议值 `13` 显示为 OSPF，`3` 显示为管理配置。`-1`、`0` 等无效或未提供的枚举显示为“未上报”，原始 SNMP 数值可将鼠标悬停在协议/类型上查看。
- 新版 CIDR 路由类型按 `other/reject/local/remote/blackhole` 解码；旧版 `ipRouteTable` 使用 `other/invalid/direct/indirect`，并跳过已失效的路由项。
- 负数路由年龄不再显示成负秒数；未提供的路由 metric 继续显示为 `-`。
- 路由表反映各设备自己的活动转发表。同一 OSPF 区域的设备拥有相同的区域链路状态库，但各设备以自身为根计算路径，因此下一跳、出接口和部分开销可能不同；完整转发表还包含设备自己的直连/静态路由、区域间汇总路由、默认路由和 ECMP 项。仅凭网络使用 OSPF 不能把 SNMP 返回的 `-1` 推断成 OSPF，标准 OSPF 协议码应为 `13`。

## 锐捷电口 SFP 识别

- 锐捷设备除标准 `ifMauType` 外，还读取 RuijieFiberMIB 的收发器类型 `.1.3.6.1.4.1.4881.1.1.10.2.105.1.1.1.165` 和连接器文本 `.1.3.6.1.4.1.4881.1.1.10.2.105.1.1.1.166`；`1000BASE-GT-SFP`、`BASE-T`、`RJ45` 等明确的铜介质会识别为电口模块并跳过无意义的 RX/TX 光功率（例如 `-40 dBm`）。
- 该识别使用接口索引映射到对应端口；不支持这些 MIB 字段的旧固件仍会尝试标准 MAU-MIB。若两者都未开放，需要设备的 SNMP walk 或对应型号 MIB 才能确认额外字段。
