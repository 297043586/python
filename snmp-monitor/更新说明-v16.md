# 第十六批更新说明

## 一、设备详情新增网络表

- 新增 **MAC 转发表**，按 `VLAN + MAC` 显示设备采集到的二层转发表项，并标明转发端口、端口角色和多位置记录。支持 Q-BRIDGE 的设备显示 VLAN 粒度；只支持传统 BRIDGE 表时 VLAN 显示为未知。
- 原 **IP-MAC-端口映射**改名为 **ARP 表**，仍展示本机 ARP 及对应的 MAC、VLAN、接口和端口；默认只看本机采集的 ARP，勾选后可追加跨设备关联记录。可以搜索 IP / MAC / 端口，并按 VLAN 筛选。
- 新增 **VLANIF / 三层接口**表，按接口合并主 IP 和额外 IP，并显示接口管理状态 / 运行状态；包含 VLANIF/SVI、管理接口和环回接口。
- VLANIF 表识别到 VLAN 编号时提供 ARP / MAC 跳转按钮，打开对应表并按 VLAN 自动筛选。
- 新增 **路由表**，优先读取标准 `inetCidrRouteTable`，并回退到 IPv4 标准表。只在打开路由标签时通过 SNMP 读取，不加入每轮巡检。
- 修复路由表遇到 `inetCidrRouteTable` 有响应但索引无法解析时提前返回 0 条的问题；继续回退 `ipCidrRouteTable` / `ipRouteTable`，并补充旧版 `ipv6RouteTable`，覆盖锐捷、H3C、华为常见标准 MIB 路径。
- ARP、MAC、VLANIF 和路由表遵守「终端与网络表」游客访问权限。
- MAC / ARP 大表仍服从 `heavy_every_n_rounds`；无历史缓存时首轮立即采集一次，之后按上次采集轮次计算间隔，跳过轮次沿用缓存。
- MAC 搜索会统一忽略大小写和冒号、点号、短横线、空格等分隔符；全网 MAC / ARP 与设备详情 ARP / MAC 表都可用不同格式搜索同一地址。
- 修复设备详情重复显示诊断：跨设备推导会先清理旧推导项和旧计数再重算，诊断区域也会合并完全相同的提示。
- 修复 H3C / 华为电口模块被误报光衰：通过收发器介质类型 MIB 识别铜缆端口并跳过 RX/TX 光功率哨兵值（如 `-40 dBm`），诊断会显示跳过数量。H3C 当前/旧版 OID 与华为 `hwEthernetPortMode` OID 都加入「设置 → 厂商 / OID」，枚举值也可配置；旧版已保存的 H3C / 华为配置会继承新默认值。锐捷官方资料确认 CLI 支持查看/切换 copper/fiber，但尚未确认可用的只读 SNMP OID，暂不预置猜测值。

## 二、MAC 数量与交换机 CLI 的差异

- 旧的设备详情 MAC 映射按 MAC 地址合并；交换机 `Dynamic Address Count` 按 VLAN 内的动态转发表项计数。同一个 MAC 在多个 VLAN 学习时，平台的旧行数会小于交换机计数。
- 新增的设备详情 MAC 转发表按 `VLAN + MAC` 保留独立项，便于与交换机的转发表行数核对。具体数量仍取决于设备是否通过 SNMP 暴露完整的 Q-BRIDGE / BRIDGE 表；页面会注明读取来源和行数。
- 全网「MAC 总表」用于归并终端位置，按 MAC 作为一个终端身份呈现，不应直接拿它的行数与单台交换机的动态 FDB 项数比较。
